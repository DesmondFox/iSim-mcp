# Flutter: UI-тулзы на bzzr_flutter

Проверено 22.10.2026: можно ли водить Flutter-приложение UI-тулзами на симуляторе (фаза 3, рабочее дерево до коммита).

| Что | Значение |
|---|---|
| Приложение | bzzr_flutter, flavor `staging`, debug: `fvm flutter build ios --simulator --debug --flavor staging -t lib/main.dart` (135 с) |
| Flutter | 3.47.5 |
| Устройство | iPhone 16 Pro Simulator, iOS 27.0, Xcode 27.1 |
| Клиент | `.build/debug/isim-mcp` по stdio |
| Экраны | приветствие → «Sign up for BZZR» → email и пароль → диалог «Cancel sign up?» → «Sign in to BZZR». Форма регистрации не отправлялась |

Для сравнения те же `paste` и `clear` прогнаны на нативном `ISimTestApp` (`make test-app`) на том же симуляторе.

## Итог

Чтение экрана, поиск, тапы и набор латиницы работают без доработок. Кириллица и эмодзи через `type_text` во Flutter-поля **не вводились**, а `clear=true` портил текст. Обе проблемы только во Flutter: на нативном поле тот же вызов отрабатывает.

## Исправлено (тот же день)

- `type_text(paste)` проверяет поле после Cmd+V. Если значение не изменилось, тулз делает долгий тап по полю и тапает «Paste» в системном меню. Кириллица с эмодзи во Flutter-поле — ~3,5 с. На нативном поле меню не нужно, работает как раньше.
- `clear`: между Cmd+A и Delete пауза 250 мс, затем ожидание, пока удаление дойдёт до поля. Если стёрся один символ, а не всё (гонка с Cmd+A), очистка повторяется с паузой 750 мс.
- После ввода тулз ждёт, пока значение поля перестанет меняться, и показывает изменившееся поле (`Field: …`), даже если оно не сообщает о фокусе. Предупреждение «text may have gone nowhere» — только если не изменилось ни одно поле. Заодно на нативных полях в отчёте больше нет обрезанного значения (`isim.test@exa` вместо полного): раньше экран читался один раз сразу после нажатий.
- Селектор: если все совпадения лежат в одном frame и интерактивно ровно одно, берётся оно. `tap {label: "Continue with Email"}` попадает в кнопку без `index`.

Повторный прогон на bzzr_flutter и `ISimTestApp` — без ошибок: латиница, вставка с `clear` и без, повторная очистка пароля той же длины, тапы по label.

## Что работает

| Тулз | Результат |
|---|---|
| `install_app`, `launch_app` | Debug-сборка Flutter в симуляторе стартует без отладчика |
| `describe_ui` | Дерево есть с первого чтения, 100–140 мс. Плоское (вложенности Flutter не отдаёт). Роли `button`, `link`, `text`, `image`, `text_field`, `secure_text_field`. `disabled` у неактивной «Continue», текст ошибки валидации виден как `[text]` |
| `describe_ui(interactive_only)` | Кнопки, ссылки и поля |
| `describe_ui(format=json)` | Работает |
| `describe_point` | Возвращает элемент под точкой, совпадает со скриншотом |
| `find_elements` | По `label` и `role` |
| `tap(element)` | По `label`: кнопки, ссылки и пункт «Paste» системного меню с ролью `text`. ~1,1 с |
| `wait_for` | `exists` и `screen_stable` |
| `type_text(method=hid)` | И в поле с фокусом, и с `element` (тап, потом ввод) |
| `press_key` | Cmd+A (выделяет всё) и Delete отдельными вызовами |
| Вставка через меню | Долгий тап по полю (`tap duration_ms=900`) → `tap {label: "Paste"}` вставляет кириллицу и эмодзи |

## Что не работало (исправлено)

1. **`type_text(method=paste)` не вставляет.** Flutter обрабатывает Cmd+V сам (`PasteTextIntent` → `Clipboard.getData`) и читает буфер программно, а не через `paste:` из UIKit. iOS отказывает без диалога «Разрешить вставку», в логе приложения: `PBErrorDomain Code=13 "Operation not authorized"`. Тулз при этом отвечал успехом. Через системное меню (см. выше) вставка проходит: это `paste:` из UIKit, ему разрешение не нужно. **Исправлено:** вставка через меню, когда Cmd+V не изменил поле.
2. **`clear=true` портит текст.** Cmd+A и Delete уходят подряд. Во Flutter выделение применяет фреймворк асинхронно, Delete приходит раньше и стирает один символ перед курсором, новый текст вставляется в середину: `isim.test@exampl.comПривеnew@example.com, мир 👋`. Если отправить Cmd+A и Delete двумя `press_key` с паузой 0,3 с, поле очищается. **Исправлено:** пауза и проверка с повтором.
3. **Ложное предупреждение о фокусе.** Flutter-поля не отдают `AXFocused`, поэтому каждый `type_text` пишет «No element reports keyboard focus, so the text may have gone nowhere», хотя текст введён. **Исправлено:** предупреждение только если ни одно поле не изменилось.

## Неудобства

4. **Подпись поля — это hint.** Пустое поле: `[text_field] "Email"`. После ввода подпись пропадает, остаётся только `value`, и `label: "Email"` поле больше не находит. Работает `role` + `index`.
5. **Роль поля пароля меняется.** Пустое — `text_field "Password"`, после ввода — `secure_text_field`, позже — снова `text_field` с `value="••••••••"`.
6. **Дубли.** У каждой «Continue with …» два элемента с одним `label` и `frame`: `[button]` и `[image]`. `tap {label: "Continue with Email"}` отвечает «2 elements match», нужен `index` или `role`. У кнопки «назад» рядом с `[button] "Cancel"` безымянный `[button]` с тем же frame. **Исправлено** для пары «кнопка + не интерактивный элемент»: берётся кнопка.
7. **`Key` не становится `identifier`.** `OnboardingKeys` (`Key('onboarding_email_field')` и т.п.) в дереве не видны, `find_elements(identifier)` ничего не находит. Нужен `Semantics(identifier: ...)` в коде приложения.
8. **Роль `text` у нажимаемого.** Пункты системного меню «Paste» и «Select All» и барьер модального диалога «Dismiss» (`[text]` на весь экран) — `text`, поэтому в `interactive_only` их нет.
9. **Устаревшие фреймы после перехода.** Экран «Sign up for BZZR» въезжает справа, и Flutter обрезает фреймы элементов по видимой части. После перехода обрезка иногда остаётся: ширина «Continue with Email» 309 или 238 pt вместо 370 (центр «Request creator account» смещён на 23 pt от видимого), и `screen_stable` считает экран стабильным, потому что дерево не меняется. Через ~20 с фреймы стали верными. Так было в двух переходах из четырёх. В одном фреймы верны сразу (16 чтений через 0,4 с). В ещё одном тап ушёл через 0,3 с после предыдущего, пока экран ещё ехал (`x=93` вместо 16): это обычная анимация, а не устаревший фрейм. Тапы по элементу при этом попадают: обрезанный фрейм лежит внутри настоящего. Неверны только координаты в `describe_ui`.

## iPhone (фаза 4)

Проверено 22.10.2026 на iPhone 14 Plus (iOS 27.0.1, USB) через агента, Flutter 3.47.5, клиент `.build/debug/isim-mcp` по stdio. Проект bzzr только читался: без сборок и записей.

**BZZR (staging), уже установленный на телефоне.** Это debug-сборка, а такие на iOS 17+ без отладчика показывают одну строку `In iOS 14+, debug mode Flutter apps can only be launched from Flutter tooling…`. Подключить и сразу отключить lldb мало: JIT-страницам отладчик нужен всё время. Поэтому приложение запускалось через `devicectl … --start-stopped`, к нему подключался lldb со скриптом, повторяющим `flutter_tools` (`lib/src/ios/lldb.dart`): точка останова на `NOTIFY_DEBUGGER_ABOUT_RX_PAGES`, запись `IHELPED!` в страницу, ручное продолжение. В приложении выполнен вход в аккаунт, поэтому проверялись только навигация и чтение: ничего не создавалось, не лайкалось и не публиковалось.

| Что | Результат |
|---|---|
| `describe_ui` | 0,3–0,4 с. Шапка, вкладки «Discover feed»/«Following feed» с `selected`, нижняя панель, посты с подписями, ссылки `[link]`, профиль (имя, подписчики, вкладки) |
| `tap` по `label` | Вкладки ленты, «Search», «Back», вкладки нижней панели. 0,7–0,9 с |
| `swipe` | Лента листается; при скролле шапка и вкладки уходят из дерева, `swipe down` их возвращает |
| `type_text` | Кириллица с эмодзи в поле поиска — напрямую; `clear` и новый запрос — с первого раза; живые результаты поиска видны |
| `describe_point` | Возвращает элемент под точкой |

Что нашлось на BZZR:

- **Скрытые элементы с пустым frame.** Flutter держит в дереве виджеты скрытых вкладок и экранов, с которых ушли, с frame `(0,0 0×0)`. `describe_ui` их не показывал, но селекторы находили: `tap {label: "Podcasts"}` отвечал «2 elements match», а `wait_for exists` «находил» скрытую вкладку. **Исправлено:** селекторы пропускают элементы без размера (на симуляторе тоже).
- **Нажимаемое без роли кнопки.** Результаты поиска и посты — `[element]` с подписью: тапаются, но в `interactive_only` их нет (как `[text]` у пунктов меню на симуляторе).
- **Безымянный `[button]`** в одном frame с «Back» и «Create», как на симуляторе.
- Первый «Back» в поиске очищает запрос, второй закрывает экран — так ведёт себя приложение.

**`flutter_probe`** — отдельное приложение в scratchpad с теми же приёмами, что в онбординге BZZR: кнопки `ElevatedButton.icon`, поля с `hintText`, `Semantics(identifier:)`, ошибка валидации, `AlertDialog` на выходе через `PopScope`, ленивый `ListView.builder` на 200 элементов, `SwitchListTile`. Profile-сборка с Personal Team — 29 с. Так проверены форма и диалог, до которых в BZZR без выхода из аккаунта не добраться.

| Что | Результат |
|---|---|
| `describe_ui` | 0,25–0,5 с. Кнопка с иконкой — один `[button]`, дублей «кнопка + картинка», как на симуляторе, нет. `Semantics(identifier:)` виден как `id=`, `disabled` у неактивной кнопки, текст ошибки, snackbar |
| `tap` по `label` | «Continue with Email», «Back», «Like» (`[switch]`, тап в правый край), кнопки диалога. 0,7–0,9 с |
| `type_text` | Латиница, кириллица и эмодзи — напрямую через агента, без буфера и меню. Поля Flutter **сообщают фокус** (на симуляторе — нет), так что в отчёте `Focused: …` |
| `type_text(clear)` | Работает с первого раза, 5–9 с (на симуляторе гонка с Cmd+A) |
| Список | `swipe` и тап по `identifier` элемента, пришедшего в экран; элементов за экраном в дереве нет (ленивый список) |
| `AlertDialog` | Текст, кнопки и барьер `[text] "Dismiss"` видны; ответ — `tap` по подписи. `handle_system_alert` его не видит: XCUITest не помечает Flutter-диалог как `alert` |

Отличия от симулятора:

1. **Запрос локальной сети.** Profile-сборка при первом запуске спрашивает «Allow “Flutter Probe” to find devices on local networks?» (VM service). `describe_ui` показывает его как системный алерт, `handle_system_alert` отвечает. Release-сборка не спрашивает.
2. **«Allow Paste».** Cmd+V во Flutter-поле читает буфер сам, и iOS на телефоне не отказывает молча, как на симуляторе, а спрашивает. `type_text(method=paste)` сообщает об этом и предлагает `handle_system_alert(accept)`, после которого текст вставляется. Пока алерт висел, первая версия тулза ждала клавиатуру у закрытого алертом приложения, и XCUITest обрабатывал «прерывание» 66 с — исправлено: агент не опрашивает приложение, которое не впереди. На iPhone вставка нужна редко: `auto` печатает любой текст напрямую.
3. **Клавиатура прыгает.** Ввод агента приходит как с аппаратной клавиатуры: iOS прячет экранную и через ~0,9 с показывает снова (это и у нативных приложений). Агент ждёт её возвращения перед следующим чтением экрана или касанием.

## Не проверено

- Формы BZZR на iPhone (регистрация, вход): в приложении выполнен вход, выходить из аккаунта не стал.
- Platform views (WebView, карты), видео и прямые эфиры.

## Что осталось

1. Пункты 1–3 и дубли «кнопка + иконка» из пункта 6 исправлены (см. «Исправлено»). Узнавать Flutter по `Frameworks/Flutter.framework` не понадобилось: `type_text` проверяет само поле.
2. Вставка через меню кладёт текст туда, где долгий тап поставил курсор (в середину поля). В короткий текст это конец строки, в длинный — середина. С `clear` неважно.
3. Устаревшие фреймы после перехода (пункт 9) — поведение Flutter, с нашей стороны не исправить. Если понадобятся точные координаты, можно перечитывать дерево, пока frame не совпадёт с элементом под точкой (`describe_point`).
4. В README добавлено для Flutter-разработчиков: `Semantics(identifier:)` вместо `Key`, выбор заполненного поля по `role` и `index`. Ещё стоит подписывать иконки-кнопки и исключать иконки внутри кнопок из семантики.
